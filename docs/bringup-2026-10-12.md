## Host validation

The first `cargo build --offline --locked --release` reached the project build
script but failed because `xtensa-esp32s3-elf-gcc` was not on `PATH`.
`~/export-esp.sh` supplied only `LIBCLANG_PATH`, consistent with the earlier
`espup install --std` instructions. The already installed linker was found under
`~/.espressif/tools/xtensa-esp-elf/esp-14.2.0_20251107/xtensa-esp-elf/bin`.

With that directory on `PATH`, the original app built successfully. The wrapper
then built the smoke test and both binaries successfully using locked dependencies.
Rust formatting and Bash syntax checks passed. GCC emitted an RWX LOAD-segment
linker warning for both binaries; it did not prevent linking or the smoke test
from running. No dependencies or global host installations were changed.

## Device validation

`espflash board-info` on `/dev/cu.usbmodem101` reported:

```text
Chip type:         esp32s3 (revision v0.2)
Crystal frequency: 40 MHz
Flash size:        16MB
Features:          WiFi, BLE, Embedded Flash
```

The smoke test was flashed with:

```sh
espflash flash --chip esp32s3 --flash-size 16mb \
    --port /dev/cu.usbmodem101 --non-interactive --skip-update-check \
    --monitor target/xtensa-esp32s3-none-elf/release/smoke-test
```

espflash reported an application image size of 85,888 bytes and a factory
partition size of 16,384,000 bytes. The boot log confirmed `SPI Flash Size : 16MB`
and loading the application from offset `0x10000`. The ESP-IDF version shown in
that boot log belongs to the bootloader bundled by the tooling; the application
itself is the team's `no_std` Rust HAL program.

USB output included:

```text
LegDay Rust smoke-test v1 | package 0.1.0 | ESP32-S3 | 240 MHz
GPIO48 toggles every 500 ms; radio and PSRAM are not initialized
LegDay Rust smoke-test v1 | LED toggle 1
LegDay Rust smoke-test v1 | LED toggle 2
LegDay Rust smoke-test v1 | LED toggle 3
```

The counter continued through `LED toggle 74`, approximately 37 seconds of
execution after the monitor's USB reset. No panic or further reset appeared in
that sequence. The monitor was closed with Ctrl+C; the flashed firmware remains
on the board. LED pin configuration and toggle execution were verified through
the source and runtime logs; the physical LED was not visually inspected.

This verifies the compiler, linker, firmware upload, boot, basic GPIO code,
delay loop, and USB output. It does not yet verify IMUs, pressure inputs, PSRAM,
radio communication, or a motion classifier.
